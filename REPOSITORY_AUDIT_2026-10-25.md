## Remaining production blockers — configuration, not fixed by waiting

1. **Netlify private-site protection:** customers/search engines cannot access the deployment until public access is deliberately enabled. This audit did not remove access protection.
2. **Firebase server credential:** configure the matching project's server-only service account in Netlify. Never put it in `VITE_` variables, source, screenshots or chat.
3. **Neon database connection:** configure the intended database securely. Verify the existing schema and back up before any approved identity transfer. This audit ran no live migrations, deletes or data transfers.
4. **Owner access:** configure the verified owner Firebase UID/email and a newly generated salted panel-password hash. A password previously shared in chat must not be reused or committed.
5. **Firebase authorized domain:** add `frutyi.netlify.app` and verify Google/email signup, verification, reset email, session restoration and logout on the actual host. Enabled provider settings alone do not prove the complete flow.
6. **Full customer verification:** after configuration, test guest and signed-in carts, saved addresses, one explicitly approved test enquiry, owner editing/uploads and actual HTTP 404/410/API statuses. Confirm the current real catalogue/image records before migrating away from Vercel.
7. **Business content:** supply/verify the seller's legal address, ingredients/allergens, storage/shelf life and delivery/return/payment terms where still missing. Newsletter and analytics remain optional; no endpoint or tracking ID was invented.
